# BUG-0001: 收官审计未覆盖跨层运行契约漂移

> 模块: test | 严重度: medium | 状态: resolved
> 发现日期: 2026-08-16 | 关联 Commit: `fix(core): harden audited runtime contracts (BUG-0001)`
> 关联日志: -

## 1 现象

- 已完成计划的收官复核同时发现 Python 3.10 编译失败、console-script `pytest` 收集失败，以及缓存、安全、轨迹、Web 和 Tool Calling 路径的契约漂移。
- 不同 URL 诊断图片可能共享缓存；高频同类 PII 会超过 Schema 上限；合法两轮补救会被轨迹评价误判；Tool 返回的资料未统一定界。
- 纯粘贴资料未生成统一摄取报告；JSON API 未复用 SSE 的超时与脱敏错误；一次资料工具调用会再次检索；不兼容的高级模型会被错误报告为实际执行层级。

## 2 诊断过程

### 假设 1：问题只是文档或计划状态过早完成

- 验证方法：分别运行 Python 3.10 编译、两种 pytest 入口，并以 fake 模型复现 Web、轨迹和 Tool Calling 边界。
- 结果：排除。失败均可由实际代码路径稳定复现，不是单纯的文档状态问题。

### 假设 2：同一能力存在彼此独立的执行或投影路径

- 验证方法：对比 JSON `graph.invoke` 与 SSE `_graph_events`，以及资料工具执行与 `_agent_result` 的检索调用。
- 结果：确认。两组路径分别实现超时/错误或检索/报告逻辑，导致安全语义和证据对象漂移。

### 假设 3：边界契约缺少自动化门禁

- 验证方法：检查现有测试是否覆盖 Python 3.10、URL 图片、101 个 PII、合法两轮补救、纯粘贴摄取、JSON 超时/脱敏、Retriever 调用次数和高级模型能力降级。
- 结果：确认。既有正常路径测试通过，但上述边界此前没有对应回归。

## 3 根因分析

- 兼容性门禁只在当前解释器和 `python -m pytest` 的部分路径上执行，未覆盖 Python 3.10 语法与 console-script 导入根目录。
- 相同领域逻辑存在双路径：`src/learning_coach/web.py` 的 JSON 与 SSE 运行边界分离，`src/learning_coach/middleware.py` 的 Tool 执行与最终来源投影各自检索。
- 部分 Schema 和流程边界在生产数据量或多轮状态下才触发：`src/learning_coach/security.py` 未在构造模型前饱和计数，`src/learning_coach/evaluation.py` 把跨轮相同事件当作同轮重放。
- 图片缓存、资料摄取和模型能力协商只覆盖了最初的 base64/文件/主路径，没有用反例锁定 URL、纯粘贴和不兼容高级模型。

## 4 修复方案

- 保持 Python 3.10+ 公开契约，改写不兼容 f-string，并让 pytest 同时包含仓库根目录和 `src`。
- 稳定序列化完整图片 block 生成缓存指纹；PII 同类计数在 Schema 上限 100 处饱和；轨迹按 `assess` 边界在同一评价轮次内判重。
- ToolMessage 统一使用既有资料定界器；纯粘贴文本始终进入 Loader/Splitter/索引管线并保留兼容字段。
- JSON 创建与答题接口消费 `_graph_events`，用 Python 3.10 兼容的绝对 deadline 统一约束锁等待与图执行；同会话 JSON/SSE 单飞，摄取移出事件循环，失败创建清理 runtime 与 lock。
- Tool 检索结果只保存在单次 runtime 并由单数来源/报告共同复用；仅让明确支持 Tool Calling 的高级模型进入 Agent 路径，否则继续主模型并报告实际层级。
- 修改范围包括 `pyproject.toml`、`README.md`、`src/learning_coach/` 对应模块以及六组回归测试。

## 6 经验教训

- “计划完成”必须同时验证公开最低 Python、README 命令入口和替代 API 路径，不能只以当前解释器的主路径测试代替。
- 同一运行语义应有单一实现和多种投影；Tool 产生的结构化证据应沿调用链复用，避免为了生成报告再次执行外部或昂贵操作。
- 多轮 State 评价必须明确轮次边界；所有有上限的 Schema 都应在输入构造处测试超过上限的饱和行为。
