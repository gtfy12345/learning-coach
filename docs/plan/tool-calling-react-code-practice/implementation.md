# Tool Calling、ReAct 与代码实践实施计划

> **版本**: 1.0
> **状态**: active
> **更新日期**: 2026-08-15

**关联 Checklist**: [implementation-checklist.md](./implementation-checklist.md)

## 1 目标

实现结构化代码实践工具、有界 ReAct 控制器、本地受限 Python 测试执行、错误分类和三级提示，并把代码练习作为兼容分支接入现有 LangGraph、SSE 与 Web。

## 2 背景

现有 Middleware 已能根据 Runtime Context 动态选择两个只读工具，并限制模型和工具调用次数，但练习仍是纯文本，评价也没有真实运行证据。第 08 阶段需要让“写代码—运行测试—根据错误继续学习”进入同一条闭环，同时避免开放式 Agent 循环和不受控代码执行。

## 3 实施步骤

### Phase 1: 工具 Schema、练习契约与动态注册表

#### 1.1 定义代码练习、测试结果、错误、提示和工具轨迹 Schema

所有结构使用 Pydantic 边界校验、禁止未知字段，并保持 State/Web 新字段可选。

#### 1.2 实现确定性 Python 练习生成器

按主题选择可执行函数练习，生成稳定 ID、Starter Code 和有界测试；不适用主题明确返回文本练习路径。

#### 1.3 实现 LangChain Tool 与阶段感知注册表

为生成和测试建立带参数 Schema 的 Tool；按阶段、练习状态和预算开放最小工具集合。

### Phase 2: 受限执行器与有界 ReAct

#### 2.1 实现 AST 策略与执行前校验

拒绝 import、危险调用、dunder、超长输入和非法入口函数，并返回安全错误摘要。

#### 2.2 实现临时目录子进程测试执行器

使用隔离解释器、最小环境、墙钟和资源上限运行有界测试，截断输出并清理临时目录。

#### 2.3 实现有界 ReAct 控制器和调用轨迹

验证 Action、阻止重复、执行动态工具并根据成功、错误或预算耗尽确定性终止。

### Phase 3: 错误分类、评分与三级提示

#### 3.1 分类语法、策略、超时、资源、运行时和断言错误

把进程与测试结果转换为稳定错误枚举和安全的测试明细。

#### 3.2 实现确定性评分与三级提示

按测试通过比例评分，针对错误类型生成方向、定位和修复范式三级提示，不泄露完整参考答案。

### Phase 4: LangGraph、SSE 与 Web 集成

#### 4.1 把代码练习接入练习生成、interrupt 与评价节点

只对适合的代码主题启用；提交代码后使用测试报告评分，文本练习继续使用模型评价。

#### 4.2 接入 State、会话 API 和 SSE 事件

新增可选练习、执行报告和工具轨迹字段，并确保暂停恢复与补救循环保留数据。

#### 4.3 实现 Web 代码输入和测试/提示展示

显示 Starter Code、测试统计、错误类别、三级提示与安全说明；动态内容继续使用安全 DOM API。

### Phase 5: 公开文档、完整验证与公众号文章

#### 5.1 更新 README 与项目边界

说明 Tool Schema、动态选择、调用上限、错误分类、执行限制、Web 使用方式和强沙箱边界。

#### 5.2 完成全量回归、文档生命周期同步与交付复盘

运行全量测试、编译、前端语法、计划上下文、索引和差异检查，并生成证据化复盘。

#### 5.3 生成并视觉检查第 08 篇公众号文章

在 `person` 目录生成 Word 文章，包含 GitHub 完整地址、架构、关键实现、安全边界和下一阶段，并逐页渲染检查。

## 4 验收标准

- 两个代码工具均有严格输入 Schema，未知字段和超限数据不会进入执行器。
- 动态注册表只开放当前阶段所需工具；ReAct 无重复调用且始终在硬上限内结束。
- 受限执行器覆盖正常、语法、策略、测试失败、运行时、超时和资源异常。
- 评分由测试通过比例确定；错误得到最多三级、逐步增强且不泄露完整答案的提示。
- 代码主题可在 Web 完成生成、提交、测试、补救或总结；原文本学习流程继续通过。
- State、JSON、SSE 和 Web 使用同一结构化报告，不泄漏临时路径、环境变量或原始异常正文。
- 完整测试通过，第 08 篇文章与实现一致并包含 `https://github.com/gtfy12345/learning-coach`。

## 5 风险与应对

| 风险 | 应对措施 |
|------|----------|
| 本地进程被误认为强沙箱 | README、报告和文章明确防护等级与公网替换要求 |
| 危险语法绕过 | AST 默认拒绝策略、dunder 禁止、最小 builtins、隔离模式和资源限制叠加 |
| 代码或输出过大 | 输入、测试数、stdout/stderr、报告字段均设硬上限 |
| Agent 循环失控 | 工具预算、内部上限、重复 Action 检测和阶段成功终止共同约束 |
| 测试分数被模型改写 | 评分由执行报告确定，模型只可参与教学表达 |
| 影响原文本练习 | 代码适用性显式判断，新字段可选，非代码主题走原路径 |
